# ACAC Evaluation Framework

ACAC means **Authorization-Constrained Annotation Correction**. It is a Python CLI evaluation framework for checking whether proposed annotation-ledger changes stay within explicit authorization, scope, and preservation constraints. It evaluates proposed changes; it is not an autonomous annotation agent and does not write to production annotation systems.

## Video walkthrough

Watch the ACAC hackathon walkthrough: [YouTube video](https://youtu.be/PTgIEro24nk).

## Why authorization matters

A change can look useful and still exceed the task. If an instruction permits changing a label but requires a memo to remain unchanged, modifying the memo is an unauthorized or collateral edit. ACAC separates the proposed patch from the rules that permit or prohibit each change and reports structural, authorization, preservation, and evidence-binding outcomes.

## Method and architecture

The v1.3.8 baseline defines case and authorization structures, predicates, temporal rules, patch validation, deterministic scoring, and audit outputs. The repository also contains a **proposed v1.4 artifact-bound evaluation path**: a bundle loader binds case, authorization, review, sidecar, reference, adjudication, lifecycle, manifest, and model-output artifacts before the coordinator allows a case into an aggregate. The proposal is not formal specification acceptance, and synthetic fixtures do not provide human approvals or gold labels.

The evaluator consumes already captured model output. It does not call a model provider. The demo uses only synthetic records, including synthetic review and approval-shaped fixtures created to exercise software validation.

## Install

Requires Python 3.11 or newer. There are no third-party runtime dependencies. From this directory:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
```

## Run the synthetic CLI demonstration

```powershell
$demoId = [guid]::NewGuid().ToString('N')
python -m acac --root . demo --output-dir "$env:TEMP\acac-demo-$demoId"
```

The demonstration writes JSON, Markdown, and self-contained HTML reports. It intentionally returns exit code 2 and reports `ineligible` because one synthetic case has unresolved authorization and is excluded from aggregation. This is expected fail-closed behavior, not a test failure. See [the synthetic demo walkthrough](docs/synthetic_demo_walkthrough.md). The records are not real human evidence, approved gold, or benchmark results.

To evaluate a supplied bundle, use `python -m acac evaluate --bundle <bundle-dir> --config <governance.json> --output-dir <new-output-dir>`. To inspect bindings without writing reports, use `python -m acac verify-bundle --bundle <bundle-dir> --config <governance.json>`. The configured approver ID is a declaration checked against the bundle; it is not identity authentication. See [the CLI guide](docs/evaluation_cli.md) for schemas, refusal behavior, and outputs.

## Tests

Run the included offline synthetic suite with:

```powershell
python -m unittest discover -s tests -v
```

These tests exercise deterministic validators, coordinator behavior, aggregation, reports, and synthetic artifact bindings. They do not run a model, inspect private reviewer or gold artifacts, or establish model performance. In the sanitized export verification on 2026-11-10, 317 tests ran: 315 passed and 2 platform-dependent symlink tests were skipped.

## Interpreting results

Structural validity, authorization outcomes, preservation, and case eligibility are separate. A structurally valid patch may still contain unauthorized edits. A matching artifact hash proves byte identity for the checked file; it does not prove the truth of its content or authenticate the person named in it. An excluded case is not silently treated as a successful score.

## Experiments and limitations

Exploratory Gemini and Qwen model-response experiments were conducted separately from the synthetic CLI demonstration. Their captures and detailed reports are not included in this public export. They are exploratory observations, not a controlled benchmark, general performance estimate, authorization-compliance proof, or model ranking.

The integrated v1.4 path is based on proposed requirements that remain unaccepted; the historic v1.3.8 requirements remain the authoritative baseline. Human interpretation, independent review, adjudication, and governance approvals cannot be generated by this software. No formal gold release or complete Phase 10 acceptance is claimed. The public export omits controlled review workflows and evidence.

## Future work

Priorities include independent review of the proposed artifact model, stronger end-to-end conformance evidence, and expansion of evaluation sets only when their source, authorization, and human evidence are appropriately governed.
