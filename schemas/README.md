The JSON files are Draft 2020-12 shape schemas. They intentionally permit M/H replacements, unknown string labels, and negative integral offsets: those can be semantic errors rather than malformed outputs. Schema validation alone cannot detect duplicate JSON member names after a permissive parser has discarded them, resolve ledger-specific addresses/types, or check patch preconditions. Use acac.contracts for authoritative staged validation. No third-party JSON Schema engine is required or silently substituted.
